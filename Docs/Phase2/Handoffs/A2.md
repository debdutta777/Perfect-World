## Design

* **The screens decide nothing.** Every price shown is `QuoteSchoolLessonAction`, every charge is the core's `ChargedUnits`, grades and diagnostics are the typed `ModelOutcome` / `ExplainOutcome` (or generic `StructureOutcome` for routine). Commands sent: `school.lesson.open`, `.choose`, `.close` only (through `IBridge`). The session id is the one the screen last displayed, so a stale screen is refused by the core (`school.session.stale_session`), not by a widget.
* **No solution is rendered or called.** The screens never read `ModelLink::Sound`, `ModelCaseDef::Fault`, `ExplainClaim::Defensible`, `ExplainEvidence::Supports/Against`, `ExplainLimitation::Bounds`, and never call a `*StandardAction` policy (the tests call it, as a player who knows the answer, never the screens). All explain claims look alike; the subtitle says more than one reading can be defended. Owed-explanation text uses the public `ModelExplanationOwed` rule query and only pre-ticks the toggle.
* **Period screen.** Binding title/brief/role are text keys; an unresolvable key falls back to the family name (title) or is hidden. Three cards: Foreground (goal picker, refused with `foreground_limit` after two), Routine (disabled with `not_secure` until the family is secure), Attend. Any `QuerySchoolPeriod` refusal (`closed_day`, `period_used`, `busy`, `not_at_bell`, `not_attending`, `history_full` ...) is shown in words and disables all three.
* **Running foreground lesson.** Units remaining with pips; case context (name, brief, unknown, seat, scarce resource, method known / unfamiliar, quantities with Given / To find); the current step's choices each with a live core quote beside it; commit buttons disabled until a choice exists. Two-pane at 1160x660 logical or more (context left, choices right), stacked below. Panes re-arrange on `Tick` (`RefreshLayout`).
* **Outcome and close.** A resolved foreground lesson shows the core's grade, diagnostics, links left out / extra (model) or evidence placed / bounded (explain), units spent, learning credit and "became secure", and offers only **Complete and close the period**. It cannot be cancelled (the core refuses that to prevent free mastery, and the button is not shown). Routine and Attend show a ready note and the same close button. After a close the screen shows a summary (time and learning credited, taken from the close events) until the player returns.
* **Cancellation.** Foreground-not-resolved, routine and attend lessons offer *Cancel lesson*; the first press arms it ("Confirm cancel", with a note that foreground slot and time are still spent and no learning is earned), the second sends `school.lesson.close` with `cancel=true` and elapsed = working units spent x 5 minutes held to period length - 1 (0 for routine / attend). `TriggerCancelLesson(n)` sends `n` exactly.
* **Routine parity.** Routine and a careful foreground run go through the identical close button; the test compares the emitted `Credited` and the day clock.
* **Leaving.** Esc / B / menu leaves **without** cancelling (first press only; auto-repeat ignored). The session is core state; constructing a new screen on the same world resumes it at its current step.
* **Words.** English comes from a code table (`GA2Entries`) that mirrors `Data/Text/en/phase2_a2.json` key for key; a test keeps them in step. A text key is never shown: unknown keys read "Text unavailable."; unknown refusal codes read "That could not be done right now." Refusal codes map to `school.session.*` keys directly and to `phase2.a2.issue.<code>` for `model.*`, `structure.*`, `dayloop.*`. When the text pipeline loads `Data/Text`, replace `PWClassLesson::FindText`'s table with the loader; nothing else changes.
* **Motion.** None. Reduced motion is respected by construction.
* **Unity safety.** No file-scope `using namespace`; every file-local name carries `A2` / `A2E` / `A2T` (model, explain, tests) and no names are shared between the three .cpp files except through `PWClassLesson`.

### Command delegates: the production bridge

`PWClassLesson::FCoreBridge` (in the header) is only an interim bridge over caller-owned state. The production bridge implements `PWClassLesson::IBridge` over the reducer. Shape (the command wrappers are the ones in `P2C_notes.md`; they do not exist in this base, so this is a sketch, not compiled code):

```cpp
class FSchoolLessonReducerBridge final : public PWClassLesson::IBridge
{
    // GetBinding / GetCatalogues: the A1 catalogue's binding and the immutable SchoolSessionCatalogues.
    // QueryPeriod: QuerySchoolPeriod(World.SchoolSessions, World.Day, Binding, Cats)
    // QueryLesson: QuerySchoolLesson(World.SchoolSessions)
    // QuoteAction: QuoteSchoolLessonAction(World.SchoolSessions, Cats, Session, Action)   // pure read
    // OpenLesson : Submit(Command{CommandSource::Player, SchoolLessonOpen{Binding.Id, Mode, Goal}})
    // ChooseAction: Submit(... SchoolLessonChoose{Session, Action})
    // CloseLesson: Submit(... SchoolLessonClose{Session, bCancel, ElapsedMinutes})
    // Map Rejection{code,...} to SchoolIssue{code} and the reducer's returned events to SchoolSessionResult.
};
```

Skill level, world seed and known alternatives for `school.lesson.open` come from the R9 authority and the current commitments **inside the bridge / reducer**, never from the screen. After any reducer change the host calls `Screen->RefreshFromSession()`. Free-roam time must stay suspended while `SchoolSessions.Active` exists (P2C notes); the screen charges nothing for reading.

### Focus restoration

* `ReturnFocusTarget` is held as `TWeakPtr<SWidget>`. `RequestLeavePanel()` (Esc, B, menu, the *Return to classroom* button) cancels pending focus work, runs `OnClosed` (the host removes the screen), then calls `FSlateApplication::SetKeyboardFocus(target, EFocusCause::SetDirectly)` if the target is still alive. If the host also restores game input mode, do it in `OnClosed`.
* While open, `PWUI::FocusWhenReady` puts focus on the first enabled control after every rebuild (goal chips, then the first mode card, then the current step's first choice, then the Close button). Up/Down/D-pad use Slate navigation; Page Up/Down and the right stick scroll the main pane.

## Unresolved assumptions and risks

1. **Production bridge, command wrappers and the `SchoolSessions` member of `WorldState` do not exist in this base.** Everything is verified against the core calls directly (`FCoreBridge`), not the reducer.
2. **Title / brief / role text keys** come from A1; this bundle does not author them. Unresolved keys are hidden (brief, role) or replaced by the family name (title).
3. **Cancel elapsed minutes** are computed by the screen (units x 5, held below the period length). That feeds the core's validated `elapsedMinutes` parameter; it is not an outcome. If you prefer the reducer to own it, pass `n` explicitly via `TriggerCancelLesson(n)` or ignore the argument in the bridge.
4. **Evidence and limitation lists are shown in authored order** and unfiltered by claim, as the core allows any combination. If shuffled presentation is wanted, the core's catalogue order is the only authority and a later order should add it there.
5. **Quote text is generic** ("Cost: 2 units (leaves 3)"); the core gives only numbers, not reasons for a price. Explanations of why something costs more (role, scarce resource) are in the seat / scarce lines of the case pane.
6. **Left in place on a reopened rebuild:** selections are kept per session and reset when the session id changes; a rebuild after an external change keeps them.
7. **Learning credit** in the summary is the sum of `Credited[].MilliXp` of the Completed event(s); the R9 accepted owner still consumes the same events (do not also sum it from the screen).

## First-compile risks (Unreal, not compiled)

* `SLATE_ARGUMENT(TWeakPtr<SWidget>, ReturnFocusTarget)` with a `TSharedPtr` passed at the call site (implicit conversion).
* `FText::Format(Text(Key), A, B, C)` relies on the implicit `FText` to `FTextFormat` conversion.
* `SNew(SHorizontalBox).Tag(...) + SHorizontalBox::Slot()` (Tag then slot operator) in `MakeChoiceRow`.
* `SAssignNew(MainScroll, SScrollBox)` inside a capturing lambda in `SPWClassLessonBase::Rebuild`.
* `TAttribute<bool>::CreateLambda` / `TAttribute<FText>::CreateLambda` capturing `this`; the lambdas live only as long as the child widgets.
* `SBox::SetContent`, `SScrollBox::SetScrollOffset` / `GetScrollOffsetOfEnd` (same calls the journal panel uses).
* Nested `?:` over differently sized `TEXT("...")` literals (array decay).
* In the tests: `Json.h` resolves to the core's `Json.h` (as in `PerfectWorldSchoolTestSupport.h`); `FGeometry()` default construction in `OnKeyDown` calls; `SButton::IsEnabled()` reflects `bEnabled` only if `MakeContentButton` passes it to `SButton` as its enabled state (assumed from `PWWidgets.cpp`).
* Aggregate `FOutcomeFacts` and `FLessonInit` are plain structs; `FLessonInit` is a protected nested type used from derived `Construct`.
