## 1. Enumeration (reproducible)

The lane's first rows are generated by `BuildFirstRows` in `PerfectWorldLaneBuildings.cpp`. For `Side` = -1 or +1 the cursor starts at `LaneX0 = -2400` and runs while `Cursor < LaneX1 - 250 = 6150`:

1. A cursor inside the side's alley band jumps to its end. The bands are -Y 4300 to 4900 and +Y 2800 to 3400.
2. `H = LaneHash(Side * 131 + 7, Index, 11)` (the `Side` argument is negative for -Y; it is a `uint32` hash).
3. `Width = 600 + 100 * (H % 6)`, cut to the alley if it would cross it, and stretched to `LaneX1` if less than 500 cm would remain. Under 300 cm it is a gap, not a building (the index does not advance).
4. `Depth = 700 + 100 * ((H >> 16) % 3)`; `Setback` = 120 / 60 / 0 for `(H >> 12) % 4` = 0 / 1 / 2 or 3; `Storeys = 3 + (H >> 8) % 3`; wall colour from `(H >> 20) % 8`, bumped by one if equal to the previous building's.
5. Frame: origin `(Cursor, Side * (400 + Setback))`, `U = +X`, `V = Side * (+Y)`. The cursor then advances by `Width`, plus 100 when `(H >> 24) % 7 == 0`.

The result is **nineteen side frontages (ten on -Y, nine on +Y)**, which matches the count in `LANE_LIFE_PLAN.md`. Three checks keep this table honest:

- A Python port of the loop reproduces the documented stationery seed `LaneHash(138, 2, 11) = 2673104671` and every footprint the existing code already names (children's home, opening home, stationery shop, tea shop).
- The same port is in `LaneFrontageCatalogueTests.cpp` (Rung 1): each catalogue row must equal what it generates.
- `PerfectWorld.KitFrontages.Recognition` (Unreal) runs the real `BuildLaneRows` and requires each row's frontage in `Scene.Fronts`.

`Fronts[0]` (-Y) and `Fronts[1]` (+Y) list the frontages in index order; `FLaneBuilding::Index` is the position in the row. **The index is a label for this document and for the pin only. A building's identity is its ID.**

### Generic ground floor today

`BuildLaneGroundFloor` picks `Mode = (Index + (Side > 0 ? 1 : 0)) % 3`:

| Mode | Treatment | What the player can do |
|---|---|---|
| 0 | **Roller shutters** with signboards over a solid shell | Nothing; sealed |
| 1 | **Open stalls** (awnings, goods, a counter inside a 100 cm niche; bay 0 is always open) over a solid shell | Look at it; sealed |
| 2 | **House door** (decorative door, lamp, barred window or shuttered bay) on a solid shell | Nothing; the door does not open; sealed |

The two end-closing masses (`Side 0`, not recorded in `Fronts`) use the same function with their own `Index`.

**Status legend** (tracked separately, as the plan requires): `yes` = done and checked at the level named in the notes; `coded` = written but not compiled or run; `no`. *Constructed* = walls with openings, floor, ceiling and the solid storeys above. *Furnished* = placed furniture with anchors, circulation and lights. *Access-integrated* = enterable through the door/access codec with a stable door ID. *Occupied* = someone lives or works there on a schedule. *Walked* = walked in a package in both cameras, with an interaction used and a door operated.
