# Perfect World agent workflow

## Model allocation

User preference: GPT-5.6 Sol and Claude Sonnet handle most tasks, with Claude Opus for difficult reviews. Use available GPT-5.6 variants for routine C++, tests, data authoring and implementation; Claude Sonnet for narrative, dialogue, design critique and a second review. Reserve Claude Opus, when available, for difficult architecture, concurrency, migration, security or stubborn debugging. Split bounded tasks with explicit file ownership. Never claim a requested model ran unless execution evidence exists. Do not silently replace an unavailable Sonnet with a more expensive model.

This file is project guidance, not a global app model setting. The desktop app's selected model is unchanged. When using the installed Claude CLI, `--model sonnet` requests its Sonnet alias; record the actual model returned by the run. Do not enable permissions bypass or recursive autonomous delegation. Never include secrets in artifacts or logs.

## Integration

When working on a complex multi-file change, discover applicable Ruflo MCP tools and use routing or shared memory if available. MCP registration alone is not agent execution. Keep generated art prompts and output provenance. Concept art is reference material, not evidence of playable assets. Avoid imposing costly systems until the slice proves their need.

## Small-step execution (latest user instruction)

Use GPT-5.6 Sol by default. Choose a single bounded change (usually one to three files), state its completion criterion, implement, run the relevant check, then record the result. Keep reasoning/context small. Sonnet complements design and reviews; Opus is reserved for genuinely difficult work. Do not launch large swarms or open-ended autonomous builds. When a model hits quota, preserve the partial files and status instead of retrying repeatedly. Report model failures accurately. A different model cannot be assumed to bypass account-wide limits.

For easy read-only checks, naming consistency, or simple mechanical edits, use a lower-cost model such as GPT-5.6 Luna when available, or deterministic tools without another model call. Keep GPT-5.6 Sol as the normal implementation choice. Escalate difficulty based on an actual unresolved issue, not file count alone.
